# 镜头类型与配比：图片是主体，解释动画是标点

## 配比是双边约束（最容易做错的一条）

用户上传的图卡是给人看的，不是拿来当模糊底用的。
只有当这句话**要解释一个机制**、或者**要强调**时，才把图糊掉在上面做动画。

| 类型 | 占比 | 作用 |
|---|---|---|
| `full` 整图铺满 | **30–65%** | 主力。图片本身就是信息 |
| `blur/hero` 模糊底 + 解释层 | **25–45%** | 讲机制、讲流程、强调一句 |
| `plain` 纯大字 | ≤ 15% | 换气口、结论句 |

实测标尺：
- `qiangfen2027`（226s / 31 镜）→ full 43.5% / blur 55.2% / chapter 1.3%
- `xingaozhong`（10 分钟 / 87 镜）→ full 20% / blur 54% / plain 20%
- `keji2027b`（142s / 25 镜）→ full 56% / hero 32% / plain 12%

**两个方向都是错。** `full` 100% 是图片轮播；`full` 8% 是把用户给的图全糊掉了
（2026-11-11 用户原话：「大部分还是用我给你上传的图片……这是为了丰富画面内容，不是让你只这么做」）。
全程只有逗号（全是解释层）和全程没有标点（全是图片）一样糟。

## 一、`full`：整图铺满

```js
{ t0: 3.533, t1: 8.500, mode: 'full', img: 'kj12' }
```

- 引擎自动加底部 `.scrim b` 压暗给字幕让位，并按镜头时长推镜。
- 推镜幅度 `amp = clamp(0.035, 0.105, dur*0.009)`，相邻镜头**推 / 拉交替**（`i % 2`）。
- **烤字图卡推镜不能超过 1.12**，否则边缘的字被切掉。
- 同一张图卡最多用两次，且中间要隔开 —— 连着用会「原地踏步」。

## 二、`blur`：模糊底 + 解释层

```css
.pic{position:absolute;inset:0;width:1920px;height:1080px;object-fit:cover;transform-origin:50% 50%}
.pic.blur{filter:blur(30px) saturate(1.15) brightness(.58);transform:scale(1.12)}
.scrim{position:absolute;inset:0;
  background:linear-gradient(90deg,rgba(4,8,13,.93) 0%,rgba(4,8,13,.86) 34%,rgba(4,8,13,.62) 62%,rgba(4,8,13,.46) 100%)}
.scrim.b{position:absolute;inset:0;
  background:linear-gradient(0deg,rgba(4,8,13,.92) 0%,rgba(4,8,13,.5) 18%,rgba(4,8,13,.14) 40%,rgba(4,8,13,0) 62%)}
```

- **`blur(30px)` 是下限。** 底图上的烤字必须被彻底糊掉；只要还能认出半个字，观众就会去读它，
  然后发现读不清，观感立刻变脏。图卡字更大时加到 32–40px。
- **`scale(1.12)`** 兜住模糊后边缘收缩露底。
- **`brightness(.58)` + 双层方向性 scrim**：左侧压得重（素材/文字在左）、底部压得重（字幕在底）。
  不要用整层压暗，会把画面闷死。

### 解释层必须有「实体」

只放 `title + 几行卡片文字` 等于「深色底 + 字」，什么都没讲。必须有下面之一：

- **3D 素材**（`hero` 版式）
- **有形状的图形组件**：柱状、阶梯、天平、流程环、时间轴、对比两侧

`check_spec.py` 会直接报错：某个 blur/hero 镜既无 `type` 也无 `mat`。

## 三、`hero`：左素材 + 右短文案（解释层主力）

```js
{ t0: 16.700, t1: 25.400, mode: 'blur', img: 'kj04', type: 'hero',
  hero: { mat: 'knowledge-puzzle-01', h: 660, x: 110, w: 660 },
  tag: '01 编程 · 真正在练什么',
  big: '复杂问题<br><em>拆成小块</em>',
  sub: '每一块都能单独验证，最后拼起来' }
```

| 字段 | 含义 |
|---|---|
| `hero.mat` | 指向 `assets/mat/<id>.png`（透明 PNG） |
| `h` | 素材高度（宽度按图片比例自动算） |
| `x` | 左边界，务必留 ≥ 90px 安全边距 |
| `w` | 只影响背后光晕宽度 |
| `y` | 素材底边，默认 830；**别超过 900**，否则压字幕 |
| `fx` | 额外 CSS filter，例：`brightness(1.32) contrast(1.06)` |
| `glow` | 光晕强度倍数，默认 1；夜色素材给 1.6–1.8 |

- `big` 86px（每行 8–9 字），`<em>` 是高亮词；`sub` 37px 一行。
- 素材自动加 `drop-shadow` + 背后 `radial-gradient` 光晕。
- 有 `type:'hero'` 时左上角**不再重复渲染** `.tag`。
- 素材右边界建议 ≤ 880px（文案区 `left:1010`）。算出宽度超了就降 `h`，不要压文案。

**暗色素材必须提亮**：夜景、深色主体直接放上去会和深色模糊底糊成一片。
`fx: 'brightness(1.3) contrast(1.06) saturate(.95)'` + `glow: 1.7` 是实测可用的一组。

## 四、`plain`：纯大字

```js
{ t0: 14.233, t1: 16.700, mode: 'plain', img: 'kj03',
  big: '编程不是<em>敲代码</em>', bigSize: 108 }
```

底图 `blur(40px) brightness(.6) saturate(1.2)`，只留一句大字。

**这两个数不能随手调小。** 早先写的是 `blur(34px) brightness(.42)`，
碰上本来就深的底图会变成近乎全黑 —— 122s 那条片子里有 7.4 秒像掉帧，用户看不出是设计还是卡了。
提亮到 `.6` 后是抽象色块；但 blur 必须同时加到 40px 以上，否则底图上的字会透出字影。

## 五、`chapter`：章节页

```js
{ t0: 35.933, t1: 40.933, mode: 'chapter', img: 't03', no: '01',
  ch: '五年，<em>究竟建了多少所高中</em>', sub: '先看几组数据' }
```

大号章号（400px）+ 标题 + 一行副标题。需要 ≥ 3 秒才立得住；
口播没有章节停顿的片子不要硬插。章号 `01` 已在画面里，**不要再写 `01 / 05`**。

## 六、`stage` / `shelf`：3D 素材进阶版式

- `stage()` —— 左素材 + 右数据区（`.stagebox` top 250 / height 630，`.sidezone` left 1140 / width 660）。
  支持 `pics`（任意摆放）、`pins`（编号圆点）、`masks`（径向遮罩 + fadeout）。
- `shelf()` —— 多个抠图元素等高归一、等间距排一条基线，标签居中在正下方。

## 七、换镜频率不等于换图

同一个底图可以连做多个镜头 —— 换的是上层内容：素材、数字、图形、文案。
观众感知到的「换镜」来自上层变化，不是底图。

反过来说：**只能靠换底图来制造变化，说明解释层缺失了；连上层都没变化，那是镜头卡住了。**

## 八、版面固定值（横屏 1920×1080）

| 项 | 值 |
|---|---|
| 字幕条 | 60px、`white-space:nowrap`、`max-width:1750`、`bottom:34`、单行 |
| 内容带 | 190–930（垂直居中用 `centerTop(h)`） |
| 标题 | 132px 起 |
| 安全边距 | 左右 ≥ 60px |
| 单镜时长上限 | 11 秒（`full` / `plain`） |

字号一档：title 106 / 卡片 74 / 列表 60 / 对比 128 / 柱状 56 / 时间轴 74 / 计数 320。
**这套字号已经放大过一轮，不要再往下调。**

## 九、转场

- 交叉溶接 `FADE = 0.30`，`on = t >= t0 && t < t1 + FADE`，`fin/fout` 取 min ——
  独立淡入淡出会在切点闪一帧黑。
- 短镜头（< 2s）的 fade 跟着缩：`fade = min(0.42, max(0.12, dur * 0.35))`。
