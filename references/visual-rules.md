# 镜头类型与配比：图片是主体，解释动画是标点

## 配比是双边约束（最容易做错的一条）

用户上传的图卡是给人看的，不是拿来当模糊底用的。
只有当这句话**要解释一个机制**、或者**要强调**时，才把图糊掉在上面做动画。

| 类型 | 占比 | 作用 |
|---|---|---|
| `full` 整图铺满 | **30–65%** | 主力。图片本身就是信息 |
| `blur` 模糊底 + 解释层 | **25–45%** | 讲机制、讲流程、强调一句 |
| `plain` 纯大字 | ≤ 15% | 换气口、结论句 |

实测标尺：
- `qiangfen2027`（226s / 31 镜）→ full 43.5% / blur 55.2% / chapter 1.3%
- `xingaozhong`（10 分钟 / 87 镜）→ full 20% / blur 54% / plain 20%
- `keji2027b`（142s / 25 镜）→ full 56% / 解释 32% / plain 12%（解释层当时用的是 3D 素材，现已停用，只抄配比）
- `期中B段`（173s / 28 镜，作者本地工程）→ **full 57% / 组件 29% / plain 14%**（全组件版，推荐）

**两个方向都是错。** `full` 100% 是图片轮播；`full` 8% 是把用户给的图全糊掉了
（2026-11-11 用户原话：「大部分还是用我给你上传的图片……这是为了丰富画面内容，不是让你只这么做」）。
全程只有逗号（全是解释层）和全程没有标点（全是图片）一样糟。

## 一、`full`：整图铺满

```js
{ t0: 3.533, t1: 8.500, mode: 'full', img: 'kj12' }
```

- 引擎自动加底部 `.scrim b` 压暗给字幕让位，并按镜头时长推镜。
- 推镜幅度 `amp = clamp(0.035, 0.105, dur*0.009)`，相邻镜头**推 / 拉交替**（`i % 2`）。
- **烤字图卡推镜不能超过 1.12**，否则边缘的字被切掉。
- 同一张图卡最多用两次，且中间要隔开 —— 连着用会「原地踏步」。

## 二、`blur`：模糊底 + 解释层

```css
.pic{position:absolute;inset:0;width:1920px;height:1080px;object-fit:cover;transform-origin:50% 50%}
.pic.blur{filter:blur(30px) saturate(1.15) brightness(.58);transform:scale(1.12)}
.scrim{position:absolute;inset:0;
  background:linear-gradient(90deg,rgba(4,8,13,.93) 0%,rgba(4,8,13,.86) 34%,rgba(4,8,13,.62) 62%,rgba(4,8,13,.46) 100%)}
.scrim.b{position:absolute;inset:0;
  background:linear-gradient(0deg,rgba(4,8,13,.92) 0%,rgba(4,8,13,.5) 18%,rgba(4,8,13,.14) 40%,rgba(4,8,13,0) 62%)}
```

- **`blur(30px)` 是下限。** 底图上的烤字必须被彻底糊掉；只要还能认出半个字，观众就会去读它，
  然后发现读不清，观感立刻变脏。图卡字更大时加到 32–40px。
- **`scale(1.12)`** 兜住模糊后边缘收缩露底。
- **`brightness(.58)` + 双层方向性 scrim**：左侧压得重（素材/文字在左）、底部压得重（字幕在底）。
  不要用整层压暗，会把画面闷死。

### 解释层必须有「实体」

只放 `title + 几行卡片文字` 等于「深色底 + 字」，什么都没讲。必须有**会动的图形组件**：
分档条、区间轨道、环形、横向条形、阶梯、上下分流、双卡对比、科目胶囊。

`check_spec.py` 会直接报错：某个 `blur` 镜没有 `type`。

字段和做法见 [explain-components.md](explain-components.md)。**3D 素材已停用**，
`hero` 版式（`hero.mat` / `h` / `x` / `w` / `y` / `fx` / `glow`）整块删除，不要再写。

### 图卡底部有烤字 → 加 `fit:true`

图卡自己带底部文字时，`cover` 铺满再推镜会把文字推出去，或者被字幕条切在字腰上：

```css
.pic.fit{inset:auto;top:0;left:50%;margin-left:-835px;width:1671px;height:940px;
  -webkit-mask-image:linear-gradient(90deg,transparent 0,rgba(0,0,0,1) 9%,rgba(0,0,0,1) 91%,transparent 100%);
  mask-image:linear-gradient(90deg,transparent 0,rgba(0,0,0,1) 9%,rgba(0,0,0,1) 91%,transparent 100%)}
.fitfade{position:absolute;left:0;right:0;top:876px;height:96px;pointer-events:none;
  background:linear-gradient(180deg,rgba(4,8,13,0) 0%,rgba(4,8,13,.72) 42%,rgba(4,8,13,.97) 100%)}
```

- 图缩到 940 高、居中、左右 9% 淡出 —— 边缘不留硬边。
- **只缩图不溶边会留一道水平硬线**，`.fitfade` 必须一起加。
- 用 `fit` 的镜头推镜压到 **1.014**，接近静帧。

## 三、解释层组件（原 `hero` 版式已删）

一镜一种组件，`mode:'blur'` + `type:'<组件名>'` + 字段。8 种形态见
[explain-components.md](explain-components.md)，这里只留选型口诀：

| 这句话在说什么 | 用哪个 |
|---|---|
| 占比区段（前 25%–50%） | `band` |
| 两值之间（从 25 到 50） | `track` |
| 单值占比（只有 20%） | `ring` |
| 多项对比（90% / 70% / 50%） | `hbars` |
| 递进台阶（+10% / +20% / +30%） | `ladder` |
| 两头分流（头部够不到、尾部跌出去） | `split` |
| 两方对峙（差 6 分） | `versus` |
| 并列项 / 科目（语数英物化） | `subj` |

```js
{ t0: 42.500, t1: 49.660, mode: 'blur', img: 'kb04', type: 'split',
  tag: '段位在哪', title: 'B+ 段 = <em>前 25%–50%</em>', foot: '中等生全挤在这一段里',
  node: 'B+',
  up: { l: '头部', v: '够不到 · 留深公办本科' },
  dn: { l: '尾部', v: '跌出 · 公办普高' } }
```

- 内容区固定在 y 300–870，`foot` 与组件不许抢空间。
- 解释层至少占满内容区 **60% 高度**，否则画面空洞。
- 组件里的数字**必须来自原稿**，不许凑。
- 8 个以上解释镜，至少用到 **5 种**形态，别全片一个样。
- 纯字镜头（没有 `type`）≤ 20%。

## 四、`plain`：纯大字

```js
{ t0: 14.233, t1: 16.700, mode: 'plain', img: 'kj03',
  big: '编程不是<em>敲代码</em>', bigSize: 108 }
```

底图 `blur(40px) brightness(.6) saturate(1.2)`，只留一句大字。

**这两个数不能随手调小。** 早先写的是 `blur(34px) brightness(.42)`，
碰上本来就深的底图会变成近乎全黑 —— 122s 那条片子里有 7.4 秒像掉帧，用户看不出是设计还是卡了。
提亮到 `.6` 后是抽象色块；但 blur 必须同时加到 40px 以上，否则底图上的字会透出字影。

**反过来，图卡上有大面积金色/红色块时 `.6` 会糊成脏斑**，要往下压到 `.46`（个别 `.34`），
blur 同步加到 46–50px。判断标准：**看不清是个色块，而不是看得见一团脏东西。**

## 五、`chapter`：章节页

```js
{ t0: 35.933, t1: 40.933, mode: 'chapter', img: 't03', no: '01',
  ch: '五年，<em>究竟建了多少所高中</em>', sub: '先看几组数据' }
```

大号章号（400px）+ 标题 + 一行副标题。需要 ≥ 3 秒才立得住；
口播没有章节停顿的片子不要硬插。章号 `01` 已在画面里，**不要再写 `01 / 05`**。

## 六、换镜频率不等于换图

同一个底图可以连做多个镜头 —— 换的是上层内容：素材、数字、图形、文案。
观众感知到的「换镜」来自上层变化，不是底图。

反过来说：**只能靠换底图来制造变化，说明解释层缺失了；连上层都没变化，那是镜头卡住了。**

## 七、版面固定值（横屏 1920×1080）

| 项 | 值 |
|---|---|
| 字幕条 | 60px、`white-space:nowrap`、`max-width:1750`、`bottom:34`、单行 |
| 字幕条底色 | **`rgba(2,5,9,.60)`** —— 60% 半透明，不要用不透明黑（会切掉图卡底部的标签/胶囊） |
| 内容带 | 190–930（垂直居中用 `centerTop(h)`） |
| 标题 | 132px 起 |
| 安全边距 | 左右 ≥ 60px |
| 单镜时长上限 | 11 秒（`full` / `plain`） |

字号一档：title 106 / 卡片 74 / 列表 60 / 对比 128 / 柱状 56 / 时间轴 74 / 计数 320。
**这套字号已经放大过一轮，不要再往下调。**

### 色板是锁死的，不要另起一套

所有工程共用这一张表。新工程直接从 [templates/text-video.html](../templates/text-video.html)
拷 CSS，**不要自己写 theme / design token**。

| 用途 | 值 | 说明 |
|---|---|---|
| 强调·青 | `#7FE3F5` | 正确的、被强调的、关键结论。渐变用 `#7FE3F5 → #8FB6FF` |
| 误读·粉 | `#F6BECE` | 只给「误区 / 例外 / 被否决的那一边」 |
| 卡片底 | `linear-gradient(180deg,rgba(30,48,68,.94),rgba(9,16,25,.96))` | 解释层卡片 |
| 卡片边 | `1px solid rgba(140,190,225,.20)` | `.hot` 换 `rgba(127,227,245,.62)` |
| 主文字 | `#FFFFFF` | 标题、数字 |
| 次级文字 | `#8FA8C2` | 标签、单位 |
| 说明文字 | `#9FB6CC` | 注释、脚注 |
| 卡片内正文 | `#C9D9E7` | 长一点的说明行 |
| 字幕条底 | `rgba(2,5,9,.60)` | 60% 半透明，别改 |

**粉色不是装饰色。** 它在这个系列里只有一个意思：这一边是错的 / 是例外。
把「强」「正确」「高分」涂成粉色，观众会读反。2026-11-23 踩过，见 explain-components.md ⑦。

## 八、转场

- 交叉溶接 `FADE = 0.30`，`on = t >= t0 && t < t1 + FADE`，`fin/fout` 取 min ——
  独立淡入淡出会在切点闪一帧黑。
- 短镜头（< 2s）的 fade 跟着缩：`fade = min(0.42, max(0.12, dur * 0.35))`。
