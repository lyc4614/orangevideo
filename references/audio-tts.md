# 口播：音色、读法、复读、响度

## 一、音色已锁定，不再试音

`tools/tts/voice_standard.json` 是唯一权威：

| 项 | 值 |
|---|---|
| 引擎 | F5-TTS 1.1.22 / `F5TTS_v1_Base` |
| 母本 | `ref_clean.wav`（原片 → demucs 人声分离 → 截 9.7s） |
| 参数 | `nfe_step 64` / `cfg_strength 2.0` / `speed 1.0` / `seed 101` |
| 后期 | `chain_a` → `acompressor` → `alimiter` → `loudnorm I=-16 TP=-1.5 LRA=11` |
| 导出 | 48kHz 单声道 / libmp3lame 192k |

**每条约片直接读这个文件，不再逐次试音。** 换参数前先问用户。

## 二、停顿表（跟标点走）

```json
{"。": 350, "；": 320, "？": 400, "！": 400, "，": 220, "paragraph": 600}
```

单位 ms。口播节奏按「数据句 / 叙述句二分」（`voice_qf.json`）——
停顿中位 336→128ms 那次改动后，超过 500ms 的死气口从 57 处降到 0 处。

## 三、数字与符号的读法要单独出来

TTS 需要口语化（「减」「除以」「百分之」），字幕要保留原符号。
`tools/tts/zh_num.py` 的 `speak()` 负责前者，字幕走原文。**别把两者混成一个字符串。**

已修过的读法：`A+`、`2027`、`5%-25%`、`610→630`。

## 四、复读检测：必须在文本层查（用户对这条最敏感）

用户的原话是「好多重复的句子，一句话的结尾读两遍」，视为严重 bug。

```bash
python tools/tts/detect_repeat.py 音频.wav
python tools/tts/detect_repeat.py 音频.wav --txt 已有的asr文本.txt
```

**为什么不能用波形比对**：F5 复读是「同一段内容念了两遍」，但两次推理采样**不逐比特相同**，
波形精确比对抓不到。文本层一定出现相邻重复短语，所以判据设在这里：

1. 相邻重复：连续两个 N-gram 完全相同（N = 4..12 字）
2. 句尾复读：某句结尾的短语在下一句开头又出现

任何一条命中都要重生成那一段，不要「反正听不太出来」。

## 五、响度：常数增益 + 限幅（**不要用 dynamic loudnorm**）

```bash
# 归一 + 直接混流（视频流 copy，不动画质）
python scripts/mkloudnorm.py --in audio/pp.wav --video out.mp4 --out 成片.mp4
# 只测响度
python scripts/mkloudnorm.py --measure 成片.mp4
# 体检：开头 0–3 秒 vs 全片有声段中位数（**交付前必跑**）
python scripts/mkloudnorm.py --check 成片.mp4
```

本系列统一：**I = -16.7±0.6 LUFS / TP ≤ -1.0 dBTP**。

### 为什么不能两遍 loudnorm

两遍 loudnorm 只有当 `linear=true` **能成立**时才是常数增益。一旦源素材
真峰值高（-0.1 dBTP）而积分响度低（-19 LUFS），「+2 dB 增益」会把峰值顶到 +1.9 dBTP，
ffmpeg 就**悄悄退化成 Dynamic**：

```
Normalization Type:   Dynamic     ← 第二遍 stderr 里就有这行，以前没人看
```

Dynamic 是**随时间变化**的增益。实测同一条 173s 的人声，每 0.2 秒的实测增益在
**-1.5 ~ +3.1 dB** 之间摆，标准差 0.88 dB。听感上就是「有的地方轻、有的地方重」，
素材本身开头偏弱时，就会变成用户说的「**开头几秒人声小，随后才变大**」。

`mkloudnorm.py` 现在的默认 `--mode flat`：

1. loudnorm 只用来**测量**（拿 input_i / input_tp）
2. `alimiter` 只压那几下最高点（attack 5ms / release 120ms / level=false）
3. **先上混成双声道再限幅** —— mono→stereo 每声道天然低 3 dB，等于白送 3 dB 峰顶余量，
   限幅要压的量从 3.7 dB 降到 0.3 dB 以内，增益曲线才真的平（实测标准差 0.36 dB，
   且开头与全片差 +0.07 dB）
4. 复测 I / TP，偏差 > 0.25 LU 自动补一次增益

`--mode loudnorm` 只为对照排查保留，**默认路径里已经没有 dynamic**。

### 交付前的「开头小声」判定

`--check` 会解码整片，逐 100ms 统计有声帧电平，输出：

```
有声段电平：前 3 秒 -20.6 dB / 全片中位 -21.3 dB / 差 +0.8 dB
逐 5 秒： 0:-21.7 5:-23.1 10:-20.5 …
```

**前 3 秒比全片中位低 1 dB 以上就报警**。这是唯一可靠的自动判定 ——
靠耳朵听「是不是开头轻」会被素材本身的语气带偏。


## 六、口播节奏要不要改，先看 CV

语速变异系数 CV（越高越像真人）。真人参考 0.172，早期 TTS 只有 0.121。
要改节奏就整段重生成 + 重新映射镜头区间（`remap_shots.py`），不要只调单句。

## 七、交付音频规格

- 48kHz、**双声道**（单声道源复制成 L/R 两路。真正的单声道文件在部分播放器 / 系统上
  会按 -3 dB 居中增益播放，听起来比预览时轻一截，用户会以为是「音频做小了」）
- AAC 192k（成片混流时）
- 不配 BGM（用户未提供曲库，历史默认静音人声）

## 八、外部音频直接当口播时

用户给真人录音（`.mp3`）+ `.srt` 时：

1. 音频**原封不动用**，不要重新 TTS，也不要重采样。
2. SRT 能用就用，但文字多半没标点 —— 走 `build_cues.py` 的双源合并，
   时间轴照抄 SRT，文字换成原稿标点。
3. 先量一遍原音频响度：可能是 -20 LUFS 甚至更低，交付前必须走 `mkloudnorm.py`。
