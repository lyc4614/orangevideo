# 口播：音色、读法、复读、响度

> **从 Word 文稿到音频的完整步骤在 [纯文稿到成片](text-to-video.md) 第 1 节**：
> 提正文（`scripts/docx_to_script.py`）→ 改成朗读稿（数字/符号/缩写的读法）→ 合成 → 验收。
> 本文只管音色、后期和响度。

## 一、已确认的配音音色

常规 F5-TTS 口播沿用 `视频制作/_tts/voice_standard.json`。用户指定「定制知识讲解男声」或「轻播客」时，用下方 Qwen3-TTS 流程。

| 项 | 值 |
|---|---|
| 引擎 | F5-TTS 1.1.22 / `F5TTS_v1_Base` |
| 母本 | `ref_clean.wav`（原片 → demucs 人声分离 → 截 9.7s） |
| 参数 | `nfe_step 64` / `cfg_strength 2.0` / `speed 1.0` / `seed 101` |
| 后期 | `chain_a` → `acompressor` → `alimiter` → `loudnorm I=-16 TP=-1.5 LRA=11` |
| 导出 | 48kHz 单声道 / libmp3lame 192k |

**使用 F5-TTS 时直接读这个文件。** 变更这套锁定参数前先问用户。

### 本地 Qwen3-TTS 轻播客口播

这套音色用于升学和知识讲解。听感以成熟、温和、有把握的普通话男声为准，保留清楚的重音和自然停顿。

1. **固定声音参考。** 复用确认过的原始试听 WAV 与逐字稿。本机可从工作区的
   `素材库/口播音色/知识讲解男声/` 找 `参考.wav` 和 `参考.txt`。首次做自己的声音时，
   用 **Qwen3-TTS 1.7B VoiceDesign** 生成并试听，例如「35 岁左右的普通话男声，像有经验的老师给成年人讲新概念，
   吐字清楚、语气平实，关键词轻微重读，句尾自然停顿」。选定后保存同一条原始试听和对应文字，后续项目直接复用。
2. **用 Base 读新稿。** 需要本地的 **Qwen3-TTS-12Hz-1.7B-Base** 权重和支持设备的 PyTorch，
   以及 `qwen-tts`、`numpy`、`soundfile` 和 FFmpeg。已验证 `qwen-tts==0.1.1`。
   `--model` 指向已下载的模型目录，本地推理无需 API 密钥。优先复用已有环境和权重。
   FFmpeg 可通过 `PATH` 或 `FFMPEG` 环境变量指定。模型和软件安装见
   [Qwen3-TTS 官方项目](https://github.com/QwenLM/Qwen3-TTS)。
   口播稿用 UTF-8 纯文本，保留标点与段落，按读法展开数字并去掉 Markdown 标记。
   字幕仍用原稿。长稿由脚本按句段和标点分批，复用同一对声音参考，再拼接整轨做一次后期。
   `--dry-out` 可以单独保留朗读干声，`--max-chars` 可调整合成分段上限。
3. **按原朗读做轻播客后期。** 先做 A 版柔化（3 kHz −3.8 dB、5.1 kHz 高频搁架 −3.2 dB、
   180 Hz 低频搁架 +1.1 dB），再做 C 版（58 Hz 高通、170 Hz +1.65 dB、335 Hz −0.85 dB、
   1.15 kHz +0.45 dB、轻压缩 1.55∶1，起音 14 ms、释放 125 ms）。
   两步各用常数增益把 RMS 电平尽量对齐到输入，优先保留峰值余量。原音频的语速、停顿、样本数和采样率照常保留。
   已有选定的单声道干声 WAV 时，用 `--input-wav` 直接处理。对已做过上述后期的音频使用现成文件。

在视频项目目录运行。示例里的脚本和模型路径替换成实际位置。

```bash
python "path/to/orangevideo/scripts/qwen3_podcast.py" --text "audio/口播稿.txt" --model "models/Qwen3-TTS-12Hz-1.7B-Base" --reference-wav "素材库/口播音色/知识讲解男声/参考.wav" --reference-text "素材库/口播音色/知识讲解男声/参考.txt" --dry-out audio/tts_raw.wav --out audio/pp.wav

# 已有干声时只做音色后期
python "path/to/orangevideo/scripts/qwen3_podcast.py" --input-wav audio/tts_raw.wav --out audio/pp.wav
```

用 `align_narration.py` 对最终 `audio/pp.wav` 按词对齐原稿并导出 SRT 和 JSON。详见[纯文稿到成片](text-to-video.md#2-依实际口播生成时间轴)。
核对专名、数字、关键句和句尾，再按第四节查复读并继续排镜。成片响度在混流阶段按第五节处理。
参考录音、参考稿和模型权重保存在本地工作区。

## 二、停顿表（跟标点走）

```json
{"。": 350, "；": 320, "？": 400, "！": 400, "，": 220, "paragraph": 600}
```

单位 ms。口播节奏按「数据句 / 叙述句二分」（`voice_qf.json`）——
停顿中位 336→128ms 那次改动后，超过 500ms 的死气口从 57 处降到 0 处。

## 三、数字与符号的读法要单独出来

TTS 需要口语化（「减」「除以」「百分之」），字幕要保留原符号。
`_tts/zh_num.py` 的 `speak()` 负责前者，字幕走原文。**别把两者混成一个字符串。**

已修过的读法：`A+`、`2027`、`5%-25%`、`610→630`。

## 四、复读检测：必须在文本层查（用户对这条最敏感）

用户的原话是「好多重复的句子，一句话的结尾读两遍」，视为严重 bug。

```bash
python _tts/detect_repeat.py 音频.wav
python _tts/detect_repeat.py 音频.wav --txt 已有的asr文本.txt
```

**为什么不能用波形比对**：F5 复读是「同一段内容念了两遍」，但两次推理采样**不逐比特相同**，
波形精确比对抓不到。文本层一定出现相邻重复短语，所以判据设在这里：

1. 相邻重复：连续两个 N-gram 完全相同（N = 4..12 字）
2. 句尾复读：某句结尾的短语在下一句开头又出现

任何一条命中都要重生成那一段，不要「反正听不太出来」。

### 但「顶针」不是复读，先量停顿

稿子本身写成顶针（`…例外的是深外初中部。深外初中部不看学区房…`）时，
文本层检测一定报警。**判据不是文本重复，是停顿长度**：

```python
# 用 ASR 分段的时间轴量两段之间的空隙
# 空隙 ≥ 0.35s  → 是两句，听着正常，不要动
# 空隙 <  0.15s  → 一定听成结巴，必须修
```

2026-11-23 实测两处顶针：一处停顿 0.50s（不动），一处 **0.00s**（听感上就是一个词念两遍）。

修法不是砍掉重复的那半句（会丢主语），而是**插入静音 + 时间轴整体平移**：

```python
INS, AT = 0.30, 137.000            # 在 AT 处插 0.30s
x, sr = sf.read('audio/pp.wav')
k, n = int(AT*sr), int(INS*sr)
sf.write('audio/pp_ins.wav', np.concatenate([x[:k], np.zeros(n, x.dtype), x[k:]]), sr)
# 然后 cues.json / cues.js / shots.js / srt 里所有 ≥ AT 的 t0/t1 一律 +INS
```

- 目标总间隙 **350–450 ms**（45 dB 阈值下量的连续低电平）
- 改完**必须重导 SRT**，只改 cues 会漏
- 批量平移用正则时，替换串**要把冒号补回去**：`r'\b(t0|t1): (\d+\.\d+)'` →
  `f'{m.group(1)}: {新值}'`。少了冒号整份 shots.js 变成 `t0132.460`，grep 关键字照样能过，很坑。

## 五、响度：常数增益 + 限幅（**不要用 dynamic loudnorm**）

```bash
# 归一 + 直接混流（视频流 copy，不动画质）
python scripts/mkloudnorm.py --in audio/pp.wav --video out.mp4 --out 成片.mp4
# 只测响度
python scripts/mkloudnorm.py --measure 成片.mp4
# 体检：开头 0–3 秒 vs 全片有声段中位数（**交付前必跑**）
python scripts/mkloudnorm.py --check 成片.mp4
```

本系列统一：**I = -16.7±0.6 LUFS / TP ≤ -1.0 dBTP**。

### 为什么不能两遍 loudnorm

两遍 loudnorm 只有当 `linear=true` **能成立**时才是常数增益。一旦源素材
真峰值高（-0.1 dBTP）而积分响度低（-19 LUFS），「+2 dB 增益」会把峰值顶到 +1.9 dBTP，
ffmpeg 就**悄悄退化成 Dynamic**：

```
Normalization Type:   Dynamic     ← 第二遍 stderr 里就有这行，以前没人看
```

Dynamic 是**随时间变化**的增益。实测同一条 173s 的人声，每 0.2 秒的实测增益在
**-1.5 ~ +3.1 dB** 之间摆，标准差 0.88 dB。听感上就是「有的地方轻、有的地方重」，
素材本身开头偏弱时，就会变成用户说的「**开头几秒人声小，随后才变大**」。

`mkloudnorm.py` 现在的默认 `--mode flat`：

1. loudnorm 只用来**测量**（拿 input_i / input_tp）
2. `alimiter` 只压那几下最高点（attack 5ms / release 120ms / level=false）
3. **先上混成双声道再限幅** —— mono→stereo 每声道天然低 3 dB，等于白送 3 dB 峰顶余量，
   限幅要压的量从 3.7 dB 降到 0.3 dB 以内，增益曲线才真的平（实测标准差 0.36 dB，
   且开头与全片差 +0.07 dB）
4. 复测 I / TP，偏差 > 0.25 LU 自动补一次增益

`--mode loudnorm` 只为对照排查保留，**默认路径里已经没有 dynamic**。

### 交付前的「开头小声」判定

`--check` 会解码整片，逐 100ms 统计有声帧电平，输出：

```
有声段电平：前 3 秒 -20.6 dB / 全片中位 -21.3 dB / 差 +0.8 dB
逐 5 秒： 0:-21.7 5:-23.1 10:-20.5 …
```

**前 3 秒比全片中位低 1 dB 以上就报警**。这是唯一可靠的自动判定 ——
靠耳朵听「是不是开头轻」会被素材本身的语气带偏。

### 报警了怎么办：给开头抬固定增益，不要开 dynamic

2026-11-23 实测：整条片已经是常数增益，`--check` 仍报「前 3 秒 -23.1 / 中位 -20.7」，差 2.4 dB。
说明**源音频前几句本来就念得轻**，跟归一化方式无关。正确修法是给那一段加**固定**增益：

```python
B, R = 4.633, 0.28                    # 抬到第一镜结束，最后 0.28s 余弦收回
g = 10**(2.3/20)
y[:int((B-R)*sr)] *= g
n = int(R*sr)
y[int((B-R)*sr):int(B*sr)] *= 1 + (g-1)*(0.5+0.5*np.cos(np.pi*np.arange(n)/n))   # g → 1
```

- 比例用 1 + (g−1)·w，**不是** g·w —— 写反了前一段直接变静音
- 抬之前先看该段峰值，`峰值 + 增益` 别顶到 0 dBFS（这次 -3.39 + 2.3 = -1.09，安全）
- 抬完重跑 `mkloudnorm.py`，`--check` 会重算中位；这次差从 −2.4 dB 收到 −0.1 dB

## 六、口播节奏要不要改，先看 CV

语速变异系数 CV（越高越像真人）。真人参考 0.172，早期 TTS 只有 0.121。
要改节奏就整段重生成 + 重新映射镜头区间（`remap_shots.py`），不要只调单句。

## 七、交付音频规格

- 48kHz、**双声道**（单声道源复制成 L/R 两路。真正的单声道文件在部分播放器 / 系统上
  会按 -3 dB 居中增益播放，听起来比预览时轻一截，用户会以为是「音频做小了」）
- AAC 192k（成片混流时）
- 不配 BGM（用户未提供曲库，历史默认静音人声）

## 八、外部音频直接当口播时

用户给真人录音（`.mp3`）+ `.srt` 时：

1. 音频**原封不动用**，不要重新 TTS，也不要重采样。
2. SRT 能用就用，但文字多半没标点 —— 走 `build_cues.py` 的双源合并，
   时间轴照抄 SRT，文字换成原稿标点。
3. 先量一遍原音频响度：可能是 -20 LUFS 甚至更低，交付前必须走 `mkloudnorm.py`。
