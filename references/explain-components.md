# 解释层：修饰卡片 + 动态数据图表

> **2026-11-17 起，3D 素材库停用。** 用户原话：「原本的 3D 素材库的素材都不是很好，不能起到对文本
> 很好的解释作用……需要重点强调和解释的部分，除了（纯大字）这种样式可以保留之外，其他的可以改用
> 修饰过的卡片和动起来的数据图表特效来做解释。」
>
> 原先的 `素材库/中考抢分3D素材包_73项/`（73 项）和 `assets-3d.md` 已归档，不要再引用、不要再往里加素材。
> 判断依据很硬：一块天平、一架阶梯、一群人偶，放在任何一句话下面都「差不多说得通」，
> 那就等于什么都没解释。**能被任何一段文稿复用的素材，就是无效素材。**

解释层只有两种合法形态：

| 形态 | 什么时候用 |
|---|---|
| **动态图表**（`band` / `track` / `ring` / `hbars` / `ladder`） | 这句话里有数量、比例、位次、名次、区间 |
| **修饰卡片**（`split` / `versus` / `subj`） | 这句话在对比两件事、或者在拆一个概念 |
| **纯大字**（`plain`） | 什么都不用画，就是要把这句话砸出來 |

## 通用骨架

所有解释层都是 `mode:'blur'` + `type`，底图是同一场景的图卡糊掉，上面压玻璃面板。

```js
{ t0: 70.140, t1: 80.840, mode: 'blur', img: 'kb07', type: 'hbars',
  tag: '特控率（一本线）',                    // 左上小标签，top 70
  title: '梯队越往前，<em>一本率越高</em>',   // 主标题，top 110，92px
  bars: [...],                                // 组件自己的数据
  foot: '再往后四十大，特控率掉到 40% 上下' } // 可选，top 810
```

| 字段 | 位置 / 规格 |
|---|---|
| `tag` | `.xtag2`，left 120 / top 70，28px + 字距 .26em |
| `title` | `.xttl`，left 120 / top 110，92px（`titleSm:true` 降 74px），`<em>` 是青色高亮 |
| `foot` | `.xfoot`，top 810，38px，居中，**只能给不占右侧空间的组件用** |

**面板底座 `.panel`**：24px 圆角 + 顶部 86px 亮线 + 三层背景（径向高光 / 竖向渐变 / 135° 渐变描边），
`box-shadow` 双层。所有卡片都套这个，否则会和背景糊在一起。

## ① `band` 分档条 —— 讲「这一段在哪」

四段等宽色块，其中一段 `.hot` 亮起。适合「X 段 = 前 25%–50%」这类**区间定位**。

```js
{ type: 'band', tag: '段位在哪', title: 'B+ 段 = <em>前 25%–50%</em>',
  foot: '中等生全挤在这一段里' }
```

- `.band` 1680×230，`gap:12`，四段 `flex:1 1 0`
- 段内 `.bk` 42px（段名）/ `.bv` 34px（区间）
- `.hot` 段：边框青色 + 内发光，`box-shadow:0 0 54px`
- 段数以 4 段为限，超过 4 段每段只剩 400px 以下，字放不下
- **必须垂直居中在内容区。** 2026-11-23 踩过：`bandTop` 硬写 380、`bandH` 290，
  卡片底边只到 670，底下空 200px，画面下半截像被裁掉了。
  引擎已改成：不给 `bandTop` 时自动 `300 + (570 − bandH)/2`。
  当「三张并列要点卡」用时 `bandH: 344`（正好占内容区 60%），四格分档条才用 230。

## ② `track` 区间轨道 —— 讲「这条线在哪」

一条 0–100% 的轨道，中间一段高亮，两端打刻度。

```js
{ type: 'track', tag: '前 25% 是谁', title: '前 25% <em>刚好是 B+ 头</em>',
  track: { from: 25, to: 50, marks: [25, 50],
           labels: ['25% · B+ 头', '50% · B+ 尾'], inner: 'B+ 段' },
  foot: '深圳的教育算广东最好的一档，所以才要 25%' }
```

- `.track` 1680×168（**不要低于 150，太薄压不住画面**）
- `from / to` 是百分比；`fill` 用 `scaleX` 生长，`transform-origin:0 50%`
- `inner` 是写在高亮块里的字，深色（`#04222E`）压在白青渐变上
- `marks` 画竖线 + 上方标签，`span` 宽 240px（**窄了会折行成「25% · / B+ 头」两行**）

## ③ `ring` 环形 —— 讲「一个比例」

```js
{ type: 'ring', tag: '把视线看长', title: '留深读本科，要 <em>前 20%</em>',
  ring: { pct: 20, label: '20%' },
  items: [ { b: '20%', t: '全省物理类，前 20% 才够' },
           { b: '职技', t: '而且只是职业技术大学本科' } ] }
```

- SVG 430×430，`r=185`，`stroke-width:30`，`stroke-linecap:round`，从 -90° 起点
- 进度用 `stroke-dashoffset` 从 `C` 到 `C*(1-pct)`，`dur` 给 1.5s
- 渐变描边走 `<linearGradient id="rg">`，`#7FE3F5 → #8FB6FF`
- 中心数字 136px，用 `background-clip:text`，**不要在这个元素里再放带 transform 的子元素**
- 右侧 `items` 每条是 `<b>数字</b><span>说明</span>`，最多 3 条
- **整组要水平居中。** 早期版本 `row.style.left='150px'` 固定，画在 1920 里右半边空 770px，
  像排版没做完。改成 `left:0; width:1920px; justify-content:center`。

## ④ `hbars` 横向条形 —— 讲「几档差多少」

```js
{ type: 'hbars', tag: '特控率（一本线）', title: '梯队越往前，<em>一本率越高</em>',
  bars: [
    { k: '前十大',   v: '>90',   u: '%', pct: 100, at: 0.6 },
    { k: '前二十大', v: '70–90', u: '%', pct: 90,  at: 2.2 },
    { k: '前四十大', v: '40–80', u: '%', pct: 80,  at: 3.9 }
  ] }
```

- 行结构：`.hbk`（右对齐）+ `.hbtrack`（含 `.hbfill`）+ `.hbv`
- **`.hbfill` 必须写 `width:100%`**，只靠 `left:0;top:0;bottom:0` 宽度是 0，条形根本不显示
  （2026-11-17 踩过，静帧里三条全是空轨道）
- `at` 是每一行的出场时间，跟着旁白一句一句亮；`pct` 是条长
- **条高 / 间距 / 起点必须按条数算，不能写死**（2026-11-19 踩过：2 条时只占内容区 47%，
  上半屏挤成一团、下半屏空一半）。现成公式：

  ```js
  const n = Math.max(2, Math.min(6, bars.length));
  const BH  = [0, 0, 120, 104, 88, 74, 60][n];
  const GAP = [0, 0, 70, 52, 36, 24, 16][n];
  const total = bars.length * (BH + GAP) - GAP;
  const budget = s.foot ? 470 : 520;         // 有 foot 就少留 50
  const top = 300 + Math.max(0, Math.min(s.foot ? 80 : 110, (budget - total) / 2));
  ```

  `.hbk` / `.hbv` 的字号也要跟着 `BH` 走（120 → 48/54，88 → 44/48，60 → 40/44），
  否则 6 条时数字会顶出右边界。
- **最多 6 条**。7 条以上不管怎么压都会撞 `foot`。
- **条序要跟口播走，不要按分数降序排。** 口播是「语文88、数学77、英语80」，
  排成 88/80/77 会让观众在第 3 秒对不上号——这是「画面和口播对不上」里最常见的一种。

## ⑤ `ladder` 阶梯 —— 讲「每上一级换多少」

```js
{ type: 'ladder', tag: '每 10 名 = 10%', title: '高中每前进 <em>10 名</em>',
  lad: [ { k: '前四十大', v: '基准' }, { k: '前三十大', v: '+10%' },
         { k: '前二十大', v: '+20%' }, { k: '前十大', v: '+30%' } ] }
```

- 柱高 `96 + i*94`，最高 378；`.lad` 高 516，top 302
- 最后一列自动 `.hot`（粉色）
- **柱高不要再加大**：总高一旦越过 820，柱下的 `.lk` 会和 `foot` 叠在一起

## ⑥ `split` 上下夹击 —— 讲「同一个东西的两个出口」

```js
{ type: 'split', tag: '同一个段，两头都危险', title: 'B+ 的 <em>上下夹击</em>',
  node: 'B+',
  up: { l: '头部', v: '够不到 · 留深公办本科' },
  dn: { l: '尾部', v: '跌出 · 公办普高' },
  foot: '差的不是努力，是那几分站在哪' }
```

- 尺寸是一道刚好的算式，**改一个数就要重算**：
  `.spl` 1680×**560**，top **290** → 占 290–850；卡 padding 26px（卡高 ~170）、
  `.splnode` **180px** 圆（`margin:-90px`）。
  560 = 170（上卡）+ 20 + 180（节点）+ 20 + 170（下卡）
- 2026-11-19 踩过：容器 500 + 节点 230 = 上下卡直接压住圆，圆被削掉小半个。
  节点和卡片之间**必须留 15–20px 的缝**，贴着就是「三块糊成一坨」。
- **这一镜不能带 `foot`。** 下卡 `bottom:0` 会到 850，`foot` 在 822 一定被卡片吞掉。
  两句都重要就把信息塞进 `up.v` / `dn.v`（每张卡 54px 一行能放 6–8 字）。
- 上下卡的 `v` **不要写成一句一样的**（「单独一条线」「单独一条线」），
  要写出区别：`按 AC 类排名` / `按 D 类排名`。
- 出场顺序：圆 → 上卡 → 下卡，间隔 ≥ 0.2s（`upAt` / `dnAt` 按台词给）

## ⑦ `versus` 双卡对比 —— 讲「A 和 B 差在哪」

```js
{ type: 'versus', tag: '只差 6 分', title: '差 <em>6 分</em> 就是一档',
  left:  { k: '深大附实验', n: '三十大梯队', v: '30' },
  right: { k: '实验光明',   n: '二十大梯队', v: '20' },
  mid:   { k: '住宿线相差', v: '6 分' },
  foot: '排名差一档，三年后的一本率差一截' }
```

- 卡 540 宽 + 中间自适应 + `gap:46`，总宽约 1300，居中；`vsTop` 默认 **318**
- **卡片必须撑得起来**：padding 54px、`vk` 36px、`vn` 52px、`vv` **142px**、`vv` 上间距 38px，
  卡高约 436，占内容区 76%。
  2026-11-19 踩过：padding 40 / vv 104 时卡只有 190px 高，卡片上下各空半个屏幕，
  和「深色底 + 三行字」一样是废画面。
- `.vsmid` 要 `display:flex;flex-direction:column;justify-content:center`，
  否则中间的差值会顶在卡片上沿（`.vs` 是 `align-items:stretch`）。
- `v` 是 142px 大字，**必须是原稿里真有的数**；稿子没给具体分数就写梯队号，不要编分数线。
  汉字也行（`文化` / `特长`），但**最多 2 字**，3 字就压到卡边。
- 左卡青色、右卡粉色，中间数字青色；中间的 `vd` 压到 84px，别和左右主数字抢（原来 100px 太抢）
- **左右颜色要能按语义改**，不然粉色会把「强」「正确」也涂成"误区色"。
  加 `col: cyan | pink | dim | white`：
  「小学学籍关联度弱 / 房产地址关联度强」→ `左 dim / 右 cyan`；
  「三个规则一致 / 一家例外」→ `左 cyan / 右 pink`（粉=例外是对的）。

## ⑧ `subj` 学科胶囊 —— 讲「其中一个就行」

```js
{ type: 'subj', tag: '新改革之后', title: '<em>一科突出</em>就能试一类自招',
  subjs: ['语文', '数学', '英语', '物理', '化学'], hot: 3,
  note: '不用每科都拔尖，<em>一科够强</em>就够得着门槛' }
```

- 胶囊横排居中，`hot` 索引那颗亮起（青边 + 56px 外发光）
- `note` 在 `subTop + 292` 处，42px，可带 `<em>`
- 只适合 4–6 项，多了会挤到屏幕外
- **只有名字的胶囊 = 没解释力。** 2026-11-23 踩过：三颗 52px 的小胶囊飘在屏幕正中，
  上下各空 200px，观众只看到三个词。要给副标题行：
  `subjs: [{k:'名额分配',s:'指标到校'}, {k:'自主招生',s:'学校自定'}]`，
  胶囊 padding 52/62、`sj` 68px、`ss` 34px，整组 `subTop: 396`。

## 排版硬规矩（都是踩出来的）

1. **内容区 y 300–870。** 组件 top 落在 300–470，底边不过 870，`foot` 在 **822**。
   低于 900 会和字幕条（890 起）打架。
   `foot` 原来写 810，6 条 hbars 的最后一条压到 800 时只剩 10px，改 822 才够。
2. **`foot` 和组件不许抢空间。** 出过两次：阶梯的 `.lk` 撞 `foot`、split 的下卡吞掉 `foot`。
   放不下就删 `foot`，别缩字号 —— 观众读不清等于没写。
3. **解释层至少占满内容区 60% 高度。** 只放一条 112px 的轨道 + 一行字，画面会有半个屏幕的空洞，
   和「深色底 + 三行字」一样是错的。
4. **一镜只用一种组件。** 不要在一镜里既放环形又放条形，观众不知道先看哪。
5. **数字必须来自原稿。** 稿子里只有「每前进 10 名，一本概率多个 10%」，就不要画成 40/50/60/70 的绝对值，
   写 `基准 / +10% / +20% / +30%`。
6. **同一个组件连着两镜用，就是卡住了。** 8 个解释镜应该至少用到 5 种不同形态。
7. **`.big` 的 line-height 是 1.30，不是 1.18。** 1.18 时两行中文字的上下几乎贴在一起
   （中文字形吃满 em 框，行距只剩 18%），看着像一坨。改 CSS 的话，
   `shots.js` 里 plain 的 `top = 545 - nl*fs*1.30/2` 要同步改，否则整块字偏上。
8. **`ladder` 最后一格会自动加 `.hot`（粉色）。** 但粉色在本系列里是「误区 / 例外」的意思，
   拿它标「最宽的那档」会读错。2026-11-23 起 `.ladcol.hot .lb` 改亮青 `#B6F4FF`。
9. **`.splcard` 宽 780**（不是 660）。660 在 1920 里只占三分之一，卡片看着像便签。
   `.splcard.up .sv` 用近白 `#E4EFF9`，「第几轮 / 看的是」不是误区，别用粉色。
10. **纯字镜里的引号用中文引号 `“ ”`**，和字幕一致。写成 `"升学"` 会在 132px 大字里露出两个竖杠。
11. **`band` 也能当「三张并列要点卡」用**，但必须开这些参数：
   `segs:[{k,v,hot}]` 自定义格子、`bandH` 高度、`bandTop` 起点、
   `segK`/`segV` 字号（默认 42/34 是给分档条用的，当卡片用要 84/42）、
   `segAt`/`segGap` 出场节奏。三格比 `subj` 胶囊信息量大得多，适合「三个锦囊」这类目录镜。

## 图卡当背景时的 `fit`

图卡底部自带标签（「三十大之外 = 极小概率留深」「住宿录取线仅差 6 分」）时，
满幅会被字幕条切在字腰上。给这一镜加 `fit: true`：

```css
.pic.fit{inset:auto;top:0;left:50%;margin-left:-835px;width:1671px;height:940px;
  -webkit-mask-image:linear-gradient(90deg,transparent 0,rgba(0,0,0,1) 9%,rgba(0,0,0,1) 91%,transparent 100%);
  mask-image:linear-gradient(90deg,...)}
.fitfade{position:absolute;left:0;right:0;top:876px;height:96px;
  background:linear-gradient(180deg,rgba(4,8,13,0) 0%,rgba(4,8,13,.72) 42%,rgba(4,8,13,.97) 100%)}
```

- 图缩到 940 高、顶部对齐，底部 140px 让给字幕条
- 左右 9% mask 淡出，否则缩小后露出图卡硬边，像画中画
- 再叠一层 `.fitfade` 溶掉底边横线（只缩图不溶边，会留一道水平硬线）
- `fit` 镜推镜幅度压到 1.014
- **每一张图卡都要单独确认底部有没有烤字**，不能按「这套都有」或「这套都没有」推测
